# Security & Access Document

## Authentication
- User accounts are authenticated via JWT tokens issued by the backend.
- Login endpoint: `POST /auth/login`
- Register endpoint: `POST /auth/register`
- Refresh endpoint: `POST /auth/refresh`
- The frontend stores the access token and refresh token in browser local storage.
- `AuthContext` uses these tokens for API requests and validates session persistence.

## Authorization
- Public GET routes are allowed without authentication: `/services/**`, `/reviews/**`, `/marketplace/**`, `/vendors/public/**`.
- `POST /auth/**`, `/swagger-ui/**`, and `/v3/api-docs/**` are also public.
- All other routes require authentication with a valid JWT access token.
- `/admin/**` is restricted to users with role `ADMIN`.

## Role Access Matrix
- Guest: browse marketplace, services, vendor profiles.
- Client: access `/client`, `/client/chat`, `/orders`, `/clients/me/*`, `/conversations`, `/reviews` (create).
- Vendor: access `/vendor/*`, `/vendors/me/*`, `/api/vendor/**`, `/conversations`, `/reviews/{reviewId}/reply`.
- Admin: access `/admin/**`, `/payments/release`, and other admin management endpoints.

## Backend Security Implementation
- Uses Spring Security with stateless JWT session handling.
- `SecurityConfig` disables CSRF and enables CORS.
- JWT filter validates authorization headers on each request.
- `PasswordEncoder` is `BCryptPasswordEncoder`.
- `AuthenticationProvider` uses custom `UserDetailsService`.
- `@EnableMethodSecurity` enables method-level security annotations.

## JWT Details
- Tokens are generated by `JwtService`.
- Access and refresh tokens include role claims.
- Tokens are validated by `JwtAuthenticationFilter` on each request.
- Tokens are signed using a secret stored in application properties.

## Sensitive Data
- Passwords are hashed, never stored in plaintext.
- `users.password` column is protected and only used for authentication.
- The backend can accept `JWT_SECRET` environment variable to override default configuration.

## Database Access Controls
- PostgreSQL stores user, order, payment, and review data.
- Foreign key constraints protect data integrity across users, vendors, services, orders, and conversations.
- `refresh_tokens` persists refresh tokens and tracks revocation status.

## Client-side Access Control
- `ProtectedRoute.jsx` checks authentication and role membership before rendering protected pages.
- Unauthorized users are redirected to `/login` or their default fallback path.
- The role map in `roleRoutes.js` defines default landing pages for each role.

## Recommended Security Improvements
- Add secure refresh token rotation and expiry enforcement.
- Move JWT secret and database credentials into a secrets manager or environment variables.
- Add request rate limiting and API throttling.
- Implement email verification for registration flows.
- Add multi-factor authentication for admin users.
- Use HTTPS in all production deployments.
